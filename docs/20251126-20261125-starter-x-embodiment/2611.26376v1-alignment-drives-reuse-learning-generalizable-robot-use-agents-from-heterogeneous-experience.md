## 摘要
视觉语言模型（VLM）在任务和领域上展现出广泛的泛化能力。然而，在机器人操作中实现可比的泛化仍然具有挑战性。机器人具身形态、任务表述、几何约定和动作接口的异构性，使跨基准和硬件的交互经验变得碎片化。我们通过对齐重新思考机器人技能学习：跨基准和具身形态的异构交互能否共同改进一套共享的机器人操作技能集？我们提出 UniCraft，一个通过对齐异构设置来学习机器人操作技能的框架。具体而言，UniCraft 使用一致的坐标约定表示观测到的场景几何，并对齐不同机器人之间的感知与控制接口。它以规范格式组织来自不同基准的任务，使交互反馈能够共同优化共享技能以及指导其选择与组合的编排策略，且无需任何演示或模型权重更新。我们交错安排来自3个基准和6种具身形态的任务，为每个智能体模型收集2,700次学习 rollout。在训练期间，UniCraft 在未见场景和任务上提升了汇总任务成功率：在 LIBERO-PRO 上提升9–28个百分点，在 RoboTwin 2.0 上提升10.8–13.3个百分点，在 RoboCasa365 上提升3.1–14.4个百分点（第1–3轮）。训练后，在学习到的技能冻结的情况下，UniCraft 在 robosuite 和 RoboDojo 上展示了跨4种新机器人具身形态和5个额外智能体模型的零样本迁移。

## Abstract
Vision-language models (VLMs) demonstrate broad generalization across tasks and domains. However, comparable generalization in robot manipulation remains challenging. Heterogeneity in robot embodiments, task formulations, geometric conventions, and action interfaces fragments interaction experience across benchmarks and hardware. We rethink robot skill learning through alignment: Can heterogeneous interactions across benchmarks and embodiments jointly improve one shared skillset for robot manipulation? We propose UniCraft, a framework for learning robot manipulation skills by aligning heterogeneous settings. Specifically, UniCraft represents observed scene geometry using consistent coordinate conventions and aligns sensing and control interfaces across robots. It organizes tasks from different benchmarks in a canonical format, allowing interaction feedback to jointly refine shared skills and the orchestration policy that guides their selection and composition, without any demonstrations or model weight updates. We interleave tasks from 3 benchmarks and 6 embodiments, collecting 2,700 learning rollouts per agent model. During training, UniCraft improves pooled task success on unseen scenarios and tasks by 9-28 percentage points on LIBERO-PRO, 10.8-13.3 on RoboTwin 2.0, and 3.1-14.4 on RoboCasa365 (Epochs 1-3). After training, with the learned skills frozen, UniCraft demonstrates zero-shot transfer across 4 new robot embodiments and 5 additional agent models on robosuite and RoboDojo.

## 1. 核心问题与研究动机

- **背景**：VLM/LLM 通过“语言 + 图像”这一统一接口对齐异构数据，实现了跨任务、跨领域的规模化训练与零样本迁移；但机器人操作领域尚不具备可比的泛化能力。
- **根本症结——异构性（heterogeneity）**：
  - 具身形态差异：运动学结构、观测空间、动作表示不同，同一数值动作在不同机器人/控制器上物理效果不同；
  - 数据层面差异：不同 benchmark 的坐标约定、标注惯例、任务表述（声明式描述 vs 可配置过程类）不一致；
  - 结果是交互经验被割裂在不同平台与基准上，采集成本高、难以迁移。
- **既有路线及其边界**：
  - VLA 路线（π0.5、X-VLA、OpenVLA-OFT 等）依赖任务特定演示学习动作预测，场景/指令/具身一变即性能骤降；
  - 交互式技能进化路线（CaP、GaP、ASPIRE、Skill2Real 等）通过代码 + 执行反馈积累可复用技能，但作用域被任务定义、硬件配置、基准套件所限定（如 Skill2Real 在 LIBERO-90 与 robosuite 上分别独立训练）。
- **三个研究问题**：(i) 对齐能否让异构任务/基准/具身的交互经验联合学习一套技能？(ii) 是否提升对未见任务与场景的泛化？(iii) 学到的技能能否迁移到未见基准与新具身？
- **整体含义**：论文主张“**对齐驱动复用**”——不是扩大模型或数据规模，而是先对齐表示与执行接口，使异构经验汇聚到同一共享技能库，从而在不做演示、不更新模型权重的前提下获得跨具身、跨基准的泛化与复用。

## 2. 方法论

### 2.1 核心思想
以“先对齐、后扩展”为原则，把**程序化技能 + 库函数 + 动作接口 + 适配器**与**编排策略（orchestration policy）**解耦：技能逻辑与具身无关，硬件差异全部下沉到适配器；异构基准统一为规范学习案例，使 rollout 反馈可联合优化同一份共享实现。

### 2.2 关键技术细节

- **统一几何表示（Aligned geometry）**
  - 场景实体表示为带类型的 `Object`：图像包围框 + 可见区域的实测位置与尺度；
  - 每个 episode 固定一个 episode-local 度量坐标系（原点 + 固定 z 轴朝上），相机适配器提供内参 K 与拍摄时刻旋转 R_t、平移 t_t；
  - 像素 (u,v) 与深度 d_t(u,v) 反投影为度量点：`p_t^w = R_t · (d_t(u,v) · K^{-1}[u,v,1]^T) + t_t`，使图像选区变成技能可推理的“米”级点；
  - 工具坐标系朝向约定：以接近轴 ẑ_a 与夹爪闭合轴 x̂_g 构造 `R_tcp = [x̂_g, ŷ_g, ẑ_a]`，`ŷ_g = (ẑ_a × x̂_g)/‖ẑ_a × x̂_g‖`，即抓取方向由目标本身承载，而非由执行设备隐含；基准已有 tool site 则继承，否则由手指几何在装配时恢复。

- **执行契约（Execution contracts）**：四层执行层级
  - 技能 `s ∈ S`：可执行过程，控制流组合库计算、动作调用与结果检查，**内部不含 LLM/VLM 调用**；
  - 库函数 `ℓ ∈ L`：对观测与设备参数做可复用计算，不下发设备命令；
  - 动作接口 `a ∈ A`：`a = (σ_a, F_a, φ_a)`，即签名、坐标/单位约定、以及在设备自身测量上评估的完成谓词；
  - 适配器 `α`：把接口绑定到原生实现；对具身 r，须满足 `A_req(r) = ∪_{s∈S_r} A_s`，且绑定必须同时保留签名、坐标系与完成谓词，返回**实测结果** ŷ 由 φ_a(ŷ) 判定成功（“已下发但未达成”即失败）。
  - 具身绑定链：`x^w → x^n → u → ŷ`（共享目标 → 原生工具系目标 → 控制器输入 → 实测结果），坐标变换、逆运动学、控制器约定全部在适配器内确定性解决，技能文本中不含任何坐标系/单位/运动学常数。
  - 示例：`actions.set_gripper()` 在 LIBERO-PRO 绑定为反复下发方向指令，在 RoboTwin 绑定为归一化开合位置目标，但都回报实测夹爪状态，因此共享技能使用同一谓词、得出同一判定。

- **规范学习案例（Canonical case）**：`c = (τ, r, e, x0)`，分别为指令与成功判据、具身、场景配置、初始状态；与各基准的配置格式解耦，执行时由基准集成调用其原生 setup 例程，成功判定用原生 success check 代替演示。

- **离线学习与进化（Reviser 循环）**
  - 学习迭代 k 的保留配置 `M_k = (S_k, A_k, L_k, π_k)`，π 为引导技能选择与组合的编排策略；
  - 案例分批 B_1…B_K；单案例 horizon `H_c = ⌈2 d_c⌉`（d_c 为参考执行长度），给出纠错余量；
  - 每批 rollout 产生反馈 F_k（原生任务结果、执行轨迹、步数），LLM Reviser 诊断共享失败机制，提出对 S/A/L 的增改或对 π 的更新；
  - **接受准则**：对验证集每个案例计算 `Δ_c = p̂_c(M̃) − p̂_c(M)`，要求**逐案例非退化** `Δ_c ≥ 0`（至少一个 >0），防止“一任务提升抵消另一任务退化”；成功率剖面不变时，用配对步数代价 `Δ_step = |P|^{-1} Σ [n_i(M̃) − n_i(M)]/d_i < 0` 比较效率；
  - 通过检查的候选（覆盖同批目标失败、相关案例、此前成功对照）构成 M_{k+1}，最终 M* 冻结部署。

- **在线操作与迁移**
  - 冻结 M* 后，编排策略 π* 引导 LLM/VLM 依据指令 g 与交互历史 h_t 合成 Python 程序 C_t；
  - 双层结构：程序内控制流（变量/分支/循环组合技能调用，并以返回值条件化后续操作）+ 程序间决策（依据输出、异常、主动请求的视觉观测合成 C_{t+1}，支持纠错重试）；
  - 跨具身迁移：目标具身从冻结技能中装配兼容模块，仅提供设备参数与满足动作需求的适配器绑定，技能实现与策略不变（如 dual ARX-X5 复用 Aloha-AgileX 的抓取/放置模块；Panda+Omron 将共享操作模块与导航组合）。

## 3. 实验设计

- **基准（5 个）**：LIBERO-PRO、RoboTwin 2.0、RoboCasa365（三者用于学习）、RoboDojo 与 robosuite（仅用于零样本迁移）。
- **学习任务池**：180 个原生任务 = LIBERO-90 的 90 个 + RoboTwin 2.0 hard 设置下 40/50 个 + RoboCasa365 预训练 50 个；覆盖固定基座单臂（Fixed Panda）、4 种双臂平台（Aloha-AgileX、dual Franka、dual Piper、dual UR5+WSG）、移动操作臂（Panda+Omron），共 **300 个任务–具身对**、**6 种具身**。
- **训练规模**：3 个 epoch × 每 epoch 6 批 × 每案例 3 次执行 = **每个智能体模型 2,700 次学习 rollout**；每 epoch 每对任务–具身换新配置与初始状态，共 900 个不同案例；每批 150 次 rollout 触发一次 harness 修订。
- **智能体模型**：GPT-6 Astra、Gemini 3.8 Flash、DeepSeek-V4.1-Flash（均高推理强度）；harness 为 Codex，技能与设备 API 以 Python 包暴露。
- **评测设置**：
  - 未见场景：LIBERO-90 / RoboTwin(40) / RC365 Atomic / RC365 Composite，共 66 案例；
  - 未见任务：LIBERO-10 / RoboTwin(10) / RC365 Composite-Unseen，共 36 任务；
  - 迁移：RoboTwin split10 于 dual ARX-X5；robosuite 11 个核心任务族（Sawyer 单臂 7 个、Baxter 与 Tiago 各 4 个双臂）；RoboDojo 全 42 任务（固定 seed 与 layout 0，每任务 5 次，共 210 次）；迁移用 6 个模型（额外 GPT-6.1 Sol、GPT-6.1 Terra、MiniMax M3.1 Flash）。
- **对比基线（4 类）**：
  - VLA：π0.5、X-VLA、OpenVLA-OFT（各基准使用各自发布的 checkpoint）；
  - 直接 EEF：MotorMind（LIBERO-PRO）、GPT-GEAR（RoboTwin）；
  - Code-as-policy：CaP-Agent0（LIBERO-PRO）、OpenRUA（ROS 2 原生接口）；
  - Agent RSI：TinyAstral、ASPIRE v1.0（基准/具身特定变体）。
  - 所有方法使用官方发布接口、无额外训练；同一 API 提供方、同一推理强度、同一硬件、同预算。
- **额外分析**：修订历史与保留率（附录 C）、组件复用与后端调用/耗时占比（Fig. 5）、失败原因分析（附录 D）、执行预算消融 1K/2K/3K/4K 步与 200 请求上限（Fig. 6）、覆盖–上下文权衡分析（附录 E）、5 个基准的执行轨迹可视化（附录 F）。

## 4. 资源与算力

- **论文未明确给出算力信息**：没有报告 GPU 型号/数量、训练或推理总时长、API 调用成本或总 token 消耗。
- 仅间接可见的规模线索：每个智能体模型 2,700 次学习 rollout（3 epoch × 6 批），6 个模型参与评测，全部在仿真中完成；作者在 Limitation 中明确提到“由于模型推理与仿真 rollout 的成本，未评估其他推理预算或更长学习日程”，说明成本是实际约束但未量化。
- 结论：**算力/成本透明度不足**，无法据此复现或估算资源需求。

## 5. 实验数量与充分性评估

- **实验体量**：
  - 学习实验：3 个智能体模型 × 3 epoch × 6 批 = 54 次修订轮次，每个模型 2,700 次 rollout；
  - 泛化实验：6 个模型–基准组合（3 模型 × 2 类未见维度，覆盖 7 个评测面板）× 3 epoch，每案例 5 次 rollout；
  - 迁移实验：4 个新具身（dual ARX-X5、Sawyer、Baxter、Tiago）+ 2 个新基准 + 5 个额外智能体模型；
  - 消融/分析：执行步数预算 4 档（1K–4K）、失败原因四类分析、修订保留率统计、组件调用占比与后端耗时分解、覆盖–上下文权衡案例回放。
- **充分性**：覆盖面在“跨基准 + 跨具身 + 跨模型”三个维度上较为罕见，尤其是同一冻结技能库在 6 个模型、4 个新具身上复用，提供了较强的复用证据；逐 epoch 报告而非只报最优点，且给出步数效率指标，可信度较高。
- **公平性措施**：同一 API 提供方与推理强度、同一每案例步数与请求上限、同一机器与硬件配置、基线均用官方接口。
- **仍存的不充分之处**：
  - 缺少**真正的消融实验**：没有“去掉几何对齐”“去掉执行契约/适配器”“单基准训练 vs 混合训练”的受控对照，因此“对齐本身带来增益”的因果归因主要靠间接论证；
  - 无随机种子方差报告（仅 3–5 次重复），无置信区间或显著性检验；
  - 修订间隔（150 rollout）、批数（6）、重复次数（5）等超参未做敏感性分析，作者自述“未系统优化”；
  - 部分基线缺列（如 X-VLA 无 RoboCasa、OpenVLA-OFT 无 RoboTwin），横向比较存在空缺格。

## 6. 主要结论与发现

- **对齐使异构经验可联合学习**：混合 3 基准、6 具身的交错训练可为每个智能体模型学出**一份**共享技能库与编排策略，且全程无演示、无权重更新。
- **泛化提升（Epoch 1→3）**：未见场景与任务上的汇总成功率提升 LIBERO-PRO 9–28 pp、RoboTwin 2.0 10.8–13.3 pp、RoboCasa365 3.1–14.4 pp；例如 Astra 在 RoboTwin 未见场景 77.5%→90.0%，RC365 Atomic 27.5%→47.5%，LIBERO-PRO 达 92.0%；未见任务上 LIBERO-10 提升 14–32 pp、RoboTwin 提升 6–11.5 pp，且六个模型–基准组合的平均执行步数全部下降（Astra 在 RoboTwin 9,864→7,609，−22.9%）。
- **相对基线的竞争力**：LIBERO-PRO 86/77/55（Astra/Gemini/DeepSeek）优于 TinyAstral（62/56/34）与 ASPIRE（62/18/16），但低于 X-VLA 的 96；RoboTwin 上 89.25/61.25/42.00 远超 X-VLA 的 10 与 GPT-GEAR 的 10/6/3；RoboCasa365 37.50/19.38/6.88 优于 π0.5 的 10.63。核心论点是“**单一共享库在异构设置上整体更强**”，而非每个单点都最优。
- **零样本迁移成立但有折损**：冻结 Astra 技能迁移到 dual ARX-X5 得 74.0%，保留参考性能的 83.6%（14.5 pp 差距归因于可达性与接触几何）；robosuite 2K 步下 Astra 66.7%、Sol 67.3%、Terra 48.0%、Gemini 28.0%、DeepSeek 32.7%、MiniMax 24.7%，4K 步下 Astra 升至 83.3%、Sol 75.3%、Terra 62.0%；RoboDojo 总体 54.8%（115/210），Memory 类最好（76.7%），Long-Horizon 最弱（42.5%）。
- **技能复用是真实的**：`pick()` 出现在 54–64% 的 rollout，`move_to()` 81–96%；修订集中在运动（29%）与抓取提案（21%）；RoboCasa 上执行占总后端时间的 70.0%，状态读取占调用的 43.9% 但仅 0.16% 时间。
- **修订机制有效但非单调**：三个模型候选修订保留率相近（38.7%/40%/39.3%）；存在验证通过却导致回归的情况（Gemini 在 RC365 Composite-Unseen 上 23.75%→17.50%→21.25%），源于覆盖–上下文权衡。
- **四类持续性失败**（附录 D）：(i) 所需能力缺失被延迟诊断（如缺少躯干高度控制）；(ii) 后续动作撤销已完成子目标（端着碗到架前但碗已掉落）——任务进度**非单调**；(iii) 难以推断可动部件对动作的响应与效果是否发生（阀门未真正旋开、门闩未释放）；(iv) 接触约束下的精细操作不可靠（插入时打滑、释放后未挂住）。

## 7. 优点

- **问题定位准确且有洞察**：把“异构性”从数据问题提升为**接口/契约问题**，用“对齐”而非“扩模型”作为复用前提，视角清晰且与 VLA 路线形成互补。
- **抽象层次设计干净**：技能 / 库函数 / 动作接口 / 适配器四层划分 + 完成谓词必须基于实测值，明确禁止“用指令值替代测量值”，这在工程上避免了大量静默失败，也让跨具身复用有明确边界。
- **几何对齐具体可落地**：统一的 episode-local 度量系、显式反投影公式、由目标承载的 TCP 朝向约定，使“图像选区 → 米级点 → 技能参数”的链路可复现。
- **接受准则严谨**：逐案例非退化约束（Δ_c ≥ 0）+ 配对步数效率比较，显式防止“以退化换提升”，比只看平均成功率的自我改进更稳健。
- **实验广度突出**：5 个基准、10 个具身、6 个智能体模型、3 个 epoch 的持续跟踪；既有源模型冻结后的跨模型复用，也有跨具身与跨基准迁移。
- **诚实的负结果分析**：专设附录剖析失败案例（含回放对照实验，如仅旁路某个停止检查即可恢复成功），并坦承覆盖–上下文权衡与验证集不保证无回归。
- **公平性控制明确**：同 API 提供方、同推理强度、同步数/请求预算、同硬件，且列出与 ASPIRE 在辅助工具（SAM2.1 vs SAM3/Contact-GraspNet/Molmo）上的差异。

## 8. 不足与局限

- **缺少关键消融，因果归因偏弱**：未提供“无对齐 / 单基准训练 / 无共享库 / 无 Reviser”的受控对照，因此“对齐驱动复用”的核心主张主要靠结果一致性支撑，而非隔离变量的实验。
- **算力与成本不透明**：无 GPU 型号/数量/时长、无 API 调用与 token 成本，难以评估方法的经济可行性与可复现性。
- **比较公平性受限**：辅助工具与预训练组件不同（分割、抓取提案、像素 grounding 的实现各异）；基线在部分基准上缺 checkpoint 或适配器（表中出现大量空缺），跨方法比较并非完全对等。
- **统计严谨性不足**：每案例 3–5 次重复，未报告方差、置信区间或显著性；3 个 epoch 的学习曲线不足以判断是否收敛或饱和。
- **超参未调优、未做敏感性分析**：修订间隔、批大小、重复次数均为固定选择，作者自述未系统优化。
- **能力边界明显**：长程组合任务表现差（RC365 Composite-Seen 仅 0–15%，RinseSinkBasin、SteamInMicrowave 三 epoch 均为 0/5）；精细插入/释放类任务不可靠；迁移存在 14.5 pp 的可达性/接触几何折损；跨模型迁移方差大（robosuite 上 24.7%–67.3%），说明**可迁移技能仍强依赖执行模型的能力**。
- **自我修订可能引发回归**：验证集通过不等于旧成功案例仍成立（CoffeeSetupMug 回放案例），存在“过拟合验证案例”的风险；覆盖–上下文权衡未给出量化解决方案。
- **仅限仿真**：所有评测在仿真中完成，未涉及真实传感器噪声、标定误差、接触动力学差异，实机迁移是明确的未来工作。
- **依赖 LLM/VLM 作为编排器**：在线程序合成依赖闭源模型 API，成本、延迟与版本漂移都会影响可复现性与部署；技能库本身虽冻结，但策略仍受模型能力约束。
