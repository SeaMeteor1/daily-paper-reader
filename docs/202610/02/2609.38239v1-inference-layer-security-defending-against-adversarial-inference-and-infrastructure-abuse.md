## 摘要
技术报告：将大型语言模型（LLM）作为服务运行不仅需要推理基础设施：提供商还必须防御试图利用该服务的对抗性交互，包括用于有害用途的越狱、复杂的拒绝服务以及蒸馏攻击。我们以一家假设的前沿实验室 Five Elements Inc. 作为贯穿全文的示例，在推理层研究这一问题。由于不存在公开的、带标注的对抗性 LLM 使用数据集，我们引入一个结构因果模型（SCM），生成一个基于现实且带标注的用户会话数据集，其中包含协同的多账户活动、平台反馈以及三个层级的标签可观测性。在该数据集上，我们训练了一个实用的梯度提升检测器，将每个用户会话分类为良性或恶意，若为恶意则判定其攻击类型。面对 oracle 标签时，该检测器几乎解决了二分类任务（AUPRC 0.993）；然而面对真实 Trust & Safety 团队会持有的运营标签，同一模型的 AUPRC 仅为 0.313：检测器比用于评估它的标签更准确。对于攻击类型归因，朴素 argmax 被 98% 的良性先验主导（宏 F1 0.295），而一个简单的阈值化决策引擎在不牺牲准确率的情况下将宏 F1 提升至 0.489。该数据集已公开发布。

## Abstract
A Technical Report: Operating a large language model (LLM) as a service requires more than inference infrastructure: the provider must also defend against adversarial interactions that seek to exploit the service, including jailbreaking for harmful use, sophisticated denial of service, and distillation attacks. We study this problem at the inference layer, using a hypothetical frontier lab, Five Elements Inc., as a running example. Because no public labelled dataset of adversarial LLM usage exists, we introduce a structural causal model (SCM) that generates a realistically grounded, labelled dataset of user-sessions, with coordinated multi-account campaigns, platform feedback, and three tiers of label observability. On this dataset we train a practical gradient-boosted detector that classifies each user-session as benign or malicious and, if malicious, by attack type. Against oracle labels the detector very nearly solves the binary task (AUPRC $0.993$), yet against the operational labels a real Trust & Safety team would hold, the same model scores an AUPRC of only $0.313$: the detector is more accurate than the labels used to evaluate it. For attack-type attribution, a naive argmax is dominated by the $98\%$ benign prior (macro-F1 $0.295$), whereas a simple thresholded decision engine raises macro-F1 to $0.489$ without sacrificing accuracy. The dataset is publicly released.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题定位**：将 LLM 作为服务运营，不仅要提供推理基础设施，还必须防御三类对抗性交互——越狱（有害使用）、复杂拒绝服务（DoS）、蒸馏攻击（能力窃取）。论文聚焦"推理层"（serving side），即模型部署后的服务端防御。
- **为什么选服务端**：
  - 模型本身的弱点（训练数据、训练过程、架构）在训练时就已冻结，部署后无法低成本更改；
  - 服务端平台拥有完全可见性和确定性控制杠杆（API 限流、内容过滤、IP/设备封禁、速率节流），与支付网络防欺诈的成熟工具箱高度可迁移；
  - 服务端干预跨模型类型、跨攻击类型通用（限流不区分后端是 GPT 还是 Qwen）。
- **现实背景**：GenAI 组织采用率从 2023 年 33% 升至 2024 年 71%，但安全栈未同步；2025 年 Google 追踪到 90 个在野零日；Anthropic 披露 DeepSeek 等用约 24,000 个欺诈账号、1,600 万+ 次交互对 Claude 进行蒸馏；墨西哥政府被单操作者用 Claude Code + GPT-4.1 攻破 10 个机构，Claude 执行了约 75% 远程命令。
- **核心痛点**：**不存在公开的、带标注的对抗性 LLM 使用数据集**。原因有三：发布真实对抗流量会暴露"漏过了多少"（声誉损失）、带来法律与监管风险、等于给攻击者一份标注好的检测器行为签名地图。
- **论文定位**：以假想前沿实验室 Five Elements Inc. 为贯穿案例，在"抽象阶梯"（Ladder of Abstraction）的 **L2（点预测器）** 层级开展研究，训练逐用户会话的二分类 + 攻击类型归因检测器。

## 2. 方法论

### 2.1 核心思想：用结构因果模型（SCM）合成带标注数据

- **拒绝独立采样**：逐列独立采样会忽略特征相关性、账户跨会话记忆、跨账户协同。真实数据中特征不是独立随机变量，而是受三重条件约束：
  - **会话内因果父节点** pa_j(·)：如 total_tokens 依赖 n_requests；
  - **账户轨迹** h_{u,<t}：用户历史会话的充分统计量（升级、覆盖饱和、地理基线）；
  - **战役共享状态** c_{C(u),t}：同一战役中账号的协同信号（越狱成功、协同爆发节拍、蒸馏进度）。
- **SCM 优势**：用 DAG 表示因果结构，按拓扑序采样，特征协变关系与真实一致；且支持**干预**（do-calculus），可做反事实查询（如"若该会话未被限流会怎样"）。

### 2.2 攻击类型分类法 C（9 类 + 1 战役级）

- 0 良性、1 蒸馏、2 越狱、3 机器人农场、4 有害使用、5 DoS、6 凭证滥用、7 数据提取、8 智能体滥用；另有战役级 `multi_surface`（跨账户聚合属性，超出逐会话预测器范围）。
- 每类对应明确的分流团队（法务、信任与安全、平台完整性、安全、威胁情报）与"漏检成本"。

### 2.3 战役生成流程（以蒸馏战役为例）

- **四层 DAG**：战役类型 C ~ Cat(θ) → 攻击者类型 A ~ Cat(φ) → 复杂度 s ~ Beta(α,β) 截断到 [s_min, s_max] → 战役细节（舰队规模、阶段排程、基础设施池）→ 逐账户实现。
- **关键参数**：蒸馏为众数战役类型（30%）；账号数 n = max(1, NegBin(r=3,p=0.3)+5)，期望约 12；阶段排程含 setup/warmup（**故意发出良性掩护流量**）/probing/active/cooldown；终止条件为领域覆盖达 0.80 或舰队被封比例达 0.70；账号创建散布随复杂度收窄（s→1 时集中在窄窗口）；基础设施复用 = 1−s；高复杂度（s>0.5）账号被烧毁后可将负载重分配至幸存者（上限 3×）。
- **逐 tick 记账**：衰减（干预倒计时）→ 清点（烧毁/中止/负载重分配）→ 阶段转换 → 共享状态更新（覆盖率 cov）→ 活动分配（slots_today）。
- **参数修饰栈**：θ(Z) = T_traj(T_camp(T_interv(θ_base(C,φ_t); Interv); c); h)，即基础参数依次经平台压力、战役协同、账户轨迹三层修饰。

### 2.4 三级标签可观测性

- **M3 oracle**：模拟器构造的真值，无延迟无噪声，仅用于评估（上限）。
- **M2 golden**：去掉隐变量，保留粗标签，加真实调查延迟（14–90 天），相当于成熟 T&S 团队多年积累的金标集。
- **M1 operational**：仅剩系统自身策略输出 + 标签噪声模型（误报、漏报、误归因）+ 延迟，是真实 T&S 团队最常持有的通道，**也是训练所用通道**。
- **信息损失层级**：M2 是 M3 的粗化+延迟，M1 是 M2 的腐蚀+延迟；三者对比可量化"标注管线"的价值。
- **账户级混淆抽样**：噪声按账户抽样（非逐会话），一次判定重新语境化整个账户历史；配套**一致回填**规则——always-adversarial 类型（如 DoS、蒸馏）回填全部历史，非 always-adversarial 类型仅从标签到达日起标注，避免时间泄漏。

### 2.5 特征工程四步

1. **裁剪地平线**：丢弃冷启动头部（n_burn_in=40）与右删失尾部（n_burn_out=320），后者是因调查延迟未到而标签虚假为良性。
2. **物化标签网格**：M3→M2→M1 三层 ×（is_adversarial, attack_type, campaign_type）= 9 列。
3. **滚动历史特征**：严格尾随 7 天窗口 W^(7)_{u,t}，计算均值/求和/最大值/计数，绝不包含未来会话。
4. **选择允许特征**：Tier 1 完全可观测（请求数、时长、token、IRT 均值/标准差、is_api/is_datacenter_ip/is_vpn、拒绝数）；Tier 2 模型派生（困惑度、安全分、查询结构熵、工具使用率、覆盖增量，**用噪声变体**）；Tier 3 派生聚合（跨账户图信号如共享 IP/设备数、注册速度、并发会话）。**排除表面标志位**（模板查询模式等），因其接近 oracle。

### 2.6 训练配方

- **模型**：XGBoost `multi:softprob`，输出 9 类概率单纯形，用 mlogloss 早停。
- **不平衡处理**：逐样本权重向量（训练流加权、验证/测试流不加权，使 mlogloss 在真实分布上估计）。
  - **Step 1 逆频率**：w_k = (N/(K·n_k))^γ；
  - **Step 2 平方根平滑** γ=1/2：将 10,000× 稀有度压缩为约 100× 权重，稳定训练；
  - **Step 3 良性钳制**：w_benign ← max(w_benign, max_{k≠benign} w_k)，防止良性类被移出梯度导致边界失学、误报激增。
- **切分协议**：时间-群体切分，按账户分区（无用户跨切分），按时间轴切分（训练严格早于验证/测试），不相交用户隐含不相交战役。

### 2.7 阈值化决策引擎

- 朴素 argmax 在 98% 良性先验下被多数类主导。改用逐类阈值 t_k，定义竞争者集合 K(p)={k: p_k ≥ t_k}，空集则弃权为良性。
- **两个杠杆**：(a) 竞争者的选择规则（绝对提升 p_k−t_k、相对提升 p_k/t_k）；(b) 良性的处理（与其他类平等竞争，或需越过更高地板 τ_b 才可选）。
- 六种策略：绝对提升、相对提升、良性地板→argmax、良性地板→绝对提升、良性地板→相对提升、元堆叠器（学习型）。

## 5. 实验数量与充分性

- **实验组数**：大致包括 3 个标签通道 × 2 个任务（二分类/多分类）、1 组朴素 argmax + 6 种决策策略对比、逐类 PR-AUC/F1 分解、SHAP 特征重要性分析，合计约 10+ 组评估。
- **充分性**：
  - 优点：三通道对照设计巧妙，能同时评估模型能力与标签质量；逐类分解揭示了"排序好但 argmax 选不出"这一关键现象；决策策略对比覆盖了多个设计维度。

## 6. 主要结论与发现

- **标签质量与模型质量同等重要**：同一检测器对 oracle 标签 AUPRC 达 0.993（近乎解决任务），对运营标签仅 0.313——**检测器比用于评估它的标签更准确**。用运营标签评估会严重低估检测器真实能力。
- **M1–M2–M3 差距量化了标注管线的价值**：M2 的 AUPRC 0.609 介于两者之间，说明金标数据集虽昂贵但确有回报。
- **朴素 argmax 被 98% 良性先验主导**：宏 F1 仅 0.295，Top-1 准确率 0.983 是假象（几乎全预测良性）。
- **阈值化决策引擎显著改善**：最强策略 #5（良性地板→相对提升）将宏 F1 从 0.295 提升至 0.489，且准确率与路由准确率同时上升，说明 argmax 把大量稀有攻击误判为良性。逐类看：蒸馏 F1 从 0.00→0.65，越狱从 0.006→0.83。
- **无单一最优策略**：#5 提升稀有类但压低 DoS/凭证滥用；#3 改善中间组但几乎不改蒸馏；#6 元堆叠器最一致（宏 F1 0.44）但维护成本高。
- **弱排序类**：agentic_misuse（PR-AUC 0.006）、data_extraction（0.135）、harmful_use（0.249）分离度差，需要更多数据或更高阶梯层级方法，而非换决策规则。
- **SHAP 特征重要性**：请求量（7 天滚动均值）最重要，其次是累计领域覆盖（蒸馏的自然信号），再次是基础设施图信号（注册速度、共享设备/IP、数据中心/API 标志），与 SCM 内置机制一致。

- **不平衡处理配方有工程价值**：逆频率 + 平方根平滑 +

良性钳制"的三步法，把 10,000× 的稀有度压到约 100×，又用良性钳制防止多数类被移出梯度，是对极端不平衡下多分类训练的一个可复用技巧。

- **阈值化决策引擎的提出有针对性**：识别出"排序能力好但 argmax 选不出"这一被忽视的失效模式，并用逐类阈值 + 竞争者选择规则 + 良性地板两条杠杆给出可操作的修正，且用六种策略的横向对比说明了没有免费午餐。
- **评估协议严谨**：时间-群体切分、按账户分区、严格尾随 7 天窗口、时间完整性回填，避免了账户泄漏、战役泄漏与未来信息泄漏，这些细节在对抗性 ML 论文中并不常见。
- **数据集公开**：将合成日志与特征矩阵发布到 Hugging Face，为后续研究提供了可复现的基准，弥补了"无公开对抗数据集"的部分空白。
- **叙事结构清晰**：以 Five Elements Inc. 这一假想前沿实验室为贯穿案例，把抽象的方法论落到具体的运营场景上，便于产业读者理解威胁模型与分流决策。

## 8. 不足与局限

- **生成器-检测器循环性（根本性局限）**：作者自承生成器编码了检测器后来恢复的启发式。这意味着数据中的"可检测信号"是由作者预设的因果机制产生的，检测器学到的是**生成器的指纹**，而非真实攻击者的行为分布。真实攻击者会自适应地规避被建模的信号，因此论文报告的 AUPRC/F1 应视为**乐观上界**。
- **单数据集、无外部验证**：全部实验在自建合成数据上完成，没有在真实（哪怕是脱敏的）服务端日志或第三方对抗数据集上交叉验证。合成分布与真实分布的差距未知，结论的外部效度受限。
- **无生成器参数敏感性分析**：战役类型先验 θ、复杂度分布 Beta(α,β)、账号数负二项参数、终止阈值（0.80 覆盖 / 0.70 被封）等关键超参均未做敏感性或消融实验，无法判断结论对这些设定的稳健性。
- **不平衡处理与决策策略在单集上调优**：逆频率平方根平滑的 γ=1/2、良性钳制规则、六种阈值策略的选择，均在测试集（或与其同源的验证集）上比较，存在选择性偏差；缺少嵌套交叉验证或独立复现。
- **未与既有不平衡方法系统对比**：只对比了朴素 argmax 与自建元堆叠器，未纳入 focal loss、类平衡采样、代价敏感学习、单类分类、异常检测等主流基线，难以定位阈值化引擎的相对优势。
- **L2 层级的固有天花板**：论文明确把研究限定在"点预测器"层级，无法处理需要跨账户聚合的 `multi_surface` 战役级攻击；对弱排序类（agentic_misuse、data_extraction、harmful_use）也承认点预测器可能不够，需上升到更高抽象层级。
- **标签噪声模型的具体形式未充分披露**：M1 的误报/漏报/误归因率、调查延迟 14–90 天的分布，以及"账户级混淆抽样"的具体实现细节，在总结层面看描述较粗，复现需依赖数据集与代码。
- **缺少在线/闭环评估**：没有模拟"检测→限流/封禁→攻击者自适应"的对抗动态，因而无法评估决策引擎在攻防博弈中的长期表现（如误封导致的用户流失成本、攻击者转向新基础设施后的性能衰减）。

## 9. 对实践的启发

- **先问"标签从哪来"，再问"模型多准"**：T&S 团队常把模型指标当作能力上限，本文指出指标本身可能才是瓶颈。投资标注管线（向 M2/M3 靠拢）的边际收益，可能高于换模型或调参。
- **不要用 argmax 部署多类检测器**：在极端先验不平衡下，argmax 会把几乎所有流量判为良性，稀有攻击的 F1 趋近于 0。应改用逐类阈值 + 良性地板，并按业务成本（漏检 vs 误报）选择竞争者规则。
- **按攻击类型分别设定策略**：没有单一阈值策略对所有类都最优——蒸馏、越狱、DoS 的最优规则不同，说明生产系统应按分流团队与漏检成本**逐类定制决策面**，而非全局一套阈值。
- **可观测性是检测器的第一性约束**：SHAP 显示最重要的特征（请求量、领域覆盖、基础设施图信号）都来自服务端可直接观测的层，说明服务端防御的杠杆确实在平台侧，且应优先采集跨账户图信号。
- **特征选择要警惕"表面标志位"**：模板查询模式等标志位接近 oracle，若在真实中不可稳定获得则会造成评估虚高；训练特征应限于部署时真实可得且不易被攻击者轻易伪造的层。
- **合成数据是权宜之计而非终点**：SCM 合成能绕过"无公开对抗数据集"的困境，但必须清醒认识到其乐观偏差，真实部署前仍需影子流量、红队与在线 A/B。

## 10. 总体评价

本文是一篇**问题定位精准、方法论有原创性、工程细节扎实**的对抗性推理防御研究。其最大贡献不在于某个检测器架构（用的是普通 XGBoost），而在于三点：**(1)** 提出用 SCM 合成带标注对抗数据，并显式建模会话内因果、账户轨迹、战役协同三重条件，使合成特征具备真实协变结构且支持反事实干预；**(2)** 构建 M3/M2/M1 三级标签可观测性框架，量化了"标注管线"本身的价值，并给出"检测器比评估它的标签更准"这一对 T&S 实践有直接冲击力的结论；**(3)** 揭示并修复了极端不平衡下 argmax 的系统性失效，用逐类阈值决策引擎把宏 F1 从 0.295 提升到 0.489。

同时必须清醒看待其局限：**生成器-检测器循环性**使得所有性能数字都应视为乐观上界；**单数据集、无外部验证、无敏感性分析**削弱了结论的外部效度；**L2 点预测器**的定位使其无法覆盖战役级与弱排序类攻击。因此，本文更适合被读作一份**方法论蓝图与可复现的合成基准**，而非可直接照搬到生产的性能承诺。后续工作的自然方向是：引入真实（脱敏）流量做域适应、加入攻击者自适应闭环、把抽象层级从 L2 上移到跨账户聚合层，以及用嵌套验证替代单集调优来检验阈值引擎的稳健性。
