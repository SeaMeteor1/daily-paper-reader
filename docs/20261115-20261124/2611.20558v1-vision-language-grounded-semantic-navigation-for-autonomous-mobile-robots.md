## 摘要
语言引导导航使移动机器人能够解释自然语言指令，并在非结构化环境中朝用户指定的目标导航。然而，将开放词汇视觉感知与用于建图和导航的经典机器人流程集成仍然是一个具有挑战性的问题。在这项工作中，我们提出了一个完整的基于ROS2的系统，该系统结合了基于前沿的探索、使用Grounding DINO的开放词汇目标检测、基于深度的三维定位以及语义建图，以在仿真中实现端到端的视觉-语言接地的导航。该系统接受诸如“去黄色盒子”之类的自然语言指令，使用文本提示从RGB图像中检测候选目标，估计它们在世界坐标系中的位置，并生成由Nav2导航栈执行的导航目标。在配备TurtleBot3机器人的基于Gazebo的室内环境中，该系统自主探索了房间，检测到五个目标物体中的三个，并成功执行了所测试的两个自然语言导航指令，且无需任务特定训练。结果表明，开放词汇接地模型可以集成到经典导航流程中，但性能受到检测不确定性、基于深度的定位误差以及探索覆盖不完整的限制。这些发现凸显了使用轻量级、仅CPU架构部署视觉-语言接地导航系统的可行性与当前局限性。

## Abstract
Language-guided navigation enables mobile robots to interpret natural language commands and navigate toward user-specified targets in unstructured environments. However, integrating open-vocabulary visual perception with classical robotics pipelines for mapping and navigation remains a challenging problem. In this work, we present a complete ROS2-based system that combines frontier-based exploration, open-vocabulary object detection using Grounding DINO, depth-based 3D localization, and semantic mapping to enable end-to-end vision-language grounded navigation in simulation. The system accepts natural language commands such as ``go to the yellow box,'' detects candidate objects from RGB images using text prompts, estimates their positions in the world frame, and generates navigation goals executed by the Nav2 stack. In a Gazebo-based indoor environment with a TurtleBot3 robot, the system autonomously explored the room, detected three of the five target objects, and successfully executed both natural language navigation commands tested, without task-specific training. The results indicate that open-vocabulary grounding models can be integrated into classical navigation pipelines, though performance is limited by detection uncertainty, depth-based localization error, and incomplete exploration coverage. These findings highlight both the feasibility and current limitations of deploying vision-language grounded navigation systems using lightweight, CPU-only architectures.

- **技术缺口**：Grounding DINO 等开放词汇检测模型支持用文本提示检测任意物体，但与经典 SLAM、代价地图、Nav2 导航栈的整合仍很困难：CPU 上单帧推理约 5–10 秒、多物体场景下检测噪声大、检测结果与 SLAM 地图及用户指令的一致性难以保证。

## 二、方法论

### 2.1 总体架构

- 系统分五层：Gazebo 仿真层、传感器处理层、感知层（Grounding DINO + 3D 定位）、规划层（Nav2）、任务控制层（有限状态机）。
- 运行分两阶段：
  - **探索阶段**：机器人用前沿策略自主探索未知环境，每移动约 1.5 m 触发一次 Grounding DINO 检测，检测结果经深度投影转为世界坐标并写入语义地图。
  - **查询阶段**：用户输入自然语言指令，解析后与语义地图匹配，生成目标位姿交由 Nav2 执行。

### 2.2 前沿探索与失败恢复

- 在 Cartographer 生成的 2D 占据栅格（0.05 m 分辨率）上，将栅格分为自由（<50）、占据（≥50）、未知（−1）。
- 将未知区域膨胀一像素后与自由区域求交，得到前沿单元；再用连通域聚类，过滤小于 k_min=3 的簇。
- 实现并比较四种前沿选择策略：
  - **Closest**：选距机器人最近的前沿质心；
  - **Largest**：选规模最大的前沿；
  - **Farthest**：选最远的前沿；
  - **Weighted**：最大化“前沿规模 /（距离+1）”，兼顾信息增益与行进代价（默认策略）。
- **自适应失败升级**：根据 Nav2 连续失败次数分四级——≤1 次用默认策略；2–3 次切到 Farthest 以逃离凹形区域；4–5 次清空已访问前沿列表并用 Farthest；≥6 次完全重置。
- **卡死检测**：若 45 秒内位移小于 0.3 m，则触发恢复或重新选点。

### 2.3 开放词汇检测

- 封装 HuggingFace 版 Grounding DINO（IDEA-Research/grounding-dino-base，约 232 M 参数），权重首次下载后本地缓存。
- 检测提示词为环境定制的一组物体描述；返回带置信度与文本标签的边界框。
- 置信度阈值 0.28（经验调参）过滤，检测按置信度降序送入 3D 定位。
- **标签清洗启发式**：当模型把多个提示词拼成一个标签（如“red cylinder blue box green cylinder”）时，将原始标签与所有提示词匹配，取最长匹配项作为单目标签。

### 2.4 深度三维定位

- **深度提取**：取边界框中心 50% 区域的深度中值，过滤 [0.1, 10.0] m 之外的值。
- **像素到相机坐标**：用针孔模型反投影，公式为
  \(p_c = [(u-c_x)d/f_x,\ (v-c_y)d/f_y,\ d]^\top\)，
  其中 \(c_x=320,\ c_y=240\)，\(f_x=f_y=w/(2\tan(\theta/2))\)，θ 为水平视场角。
- **相机到世界坐标**：通过 ROS2 TF 树取得相机到世界的齐次变换 \(T_{cw}\)，计算 \(p_w = T_{cw} p_c\)；TF 查询失败时回退到里程计位姿加固定相机-机器人变换。
- **已识别的误差源**：Gazebo SDF 定义 HFOV=1.086 rad（62.2°），对应 \(f_x=530.5\)，而代码硬编码 69.4°，对应 \(f_x=462.1\)，约 13% 焦距失配直接贡献定位误差。

### 2.5 语义地图

- 每个条目包含标签、三维世界坐标、置信度、时间戳、观测计数。
- **重复合并**：同标签且距离小于 d_merge=0.5 m 时，用加权滑动平均更新位置：
  \(p_{new} = (n\,p_{old} + p_{det})/(n+1)\)，
  置信度取新旧最大值，观测计数加一。
- 支持模糊子串（大小写不敏感）、精确匹配、最近位置、球形空间区域等查询；可序列化为 JSON，支持跨会话增量建图。

### 2.6 自然语言指令解析

- 采用正则表达式级联，刻意避免 LLM 推理，保证确定性、易调试、无外部 API 依赖。
- 四阶段流程：
  1. **动作识别**：匹配 go to、navigate to、move to、find、locate、where is、explore 等；
  2. **空间关系抽取**：匹配 near、behind 等介词及其参照物；
  3. **属性抽取**：从红、蓝、绿、黄、白五色词表中提取颜色修饰；
  4. **目标抽取**：剩余文本作为目标标签（本环境中为 box 或 cylinder）。
- 输出结构化 `ParsedCommand`，属性+目标（如“blue box”）组成查询文本。

### 2.7 任务控制器

- 五状态有限状态机：IDLE、EXPLORING、DETECTING、NAVIGATING、FAILED。
- 通过 `/user_command` 接收“start exploration”或导航指令；导航目标经 `/navigate_to_pose` 动作接口交给 Nav2。
- 订阅图像、深度、里程计；向 `/navigation_status` 发布遥测，向 `/semantic_map/add` 发布新检测；每次成功检测后自动落盘保存语义地图。

## 三、实验设计

- **仿真平台**：Gazebo Classic 11 + TurtleBot3 Waffle Pi 差速机器人，ODE 物理，步长 0.001 s。
- **传感器**：360° HLS-LFCD LiDAR（0.12–3.5 m）、640×480 RGB 相机（62.2° HFOV）、同位置深度相机（32 位浮点深度图）。
- **场景**：8 m × 8 m 室内房间，2.5 m 高墙；五个固定位置几何物体——红圆柱 (−2, 2)、蓝盒 (2, 2)、绿圆柱 (−2, −2)、黄盒 (2.5, −2.5)、白圆柱 (2.5, 0.5)；机器人从原点出发。
- **建图与导航**：Cartographer SLAM 生成 0.05 m 占据栅格并以 1 Hz 发布；Nav2 负责全局规划与局部代价地图避障。
- **Benchmark**：没有使用公开标准 benchmark，而是自建单房间仿真场景；评价指标为探索覆盖率、导航目标成功率、检测类别与位置误差、自然语言指令执行成功率。
- **对比方法**：仅对四种前沿选择策略（Closest / Largest / Farthest / Weighted）做了开发过程中的定性比较，其中 Closest 因目标落入 Nav2 0.25 m 容差导致“未移动即报成功”的退化行为；未与 SayPlan、LM-Nav、ConceptFusion 等外部系统做定量对比。
- **实验流程**：每次从原点、空语义地图开始，探索最多 15 分钟或直至无前沿；探索结束后发出自然语言指令并记录是否到达。

## 六、主要结论与发现

- **可行性结论**：开放词汇 grounding 模型可以嵌入经典 ROS2 建图-导航管线，在纯 CPU 商品硬件上完成“自主探索 → 语义建图 → 自然语言目标导航”的端到端流程，且无需任务特定训练。
- **探索策略发现**：Closest 前沿策略会频繁选中落在 Nav2 0.25 m 目标容差内的前沿，导致机器人“未移动即报告成功”的退化行为；Weighted 策略通过平衡前沿规模与距离避免了该问题，自适应失败恢复也在机器人卡住时帮助其脱困。
- **检测发现**：五个目标中检出三个（黄盒、红圆柱置信度 0.51，绿圆柱 0.46）；蓝盒因探索轨迹主要覆盖房间左半部而未进入检测范围；白圆柱因与浅色墙面低对比度未被正确检出，唯一相关条目是位于房间外的虚假匹配。
- **定位精度**：正确检出物体的最佳位置估计与真值偏差 0.3–2.4 m，黄盒与绿圆柱约 0.3 m，红圆柱约 2.4 m；误差来源包括远距离深度误差、HFOV 失配、TF 位姿累积误差。
- **指令执行**：两条测试指令均被正确解析、成功命中语义地图（子串查询可容忍标签拼接），Nav2 均报告到达存储地图位置；但“到达地图点”不等于“到达真实物体”，红圆柱场景实际偏差约 2.4 m。
- **解析器结论**：正则解析对测试指令足够，且规避了 LLM 的延迟与部署复杂度。

## 七、优点

- **系统集成完整度高**：把探索、检测、定位、建图、解析、导航六个模块在 ROS2 中打通，形成可运行的开源端到端系统，工程参考价值明确。

- **确定性与可调试性**：以正则解析替代 LLM 规划，牺牲表达能力换取可复现、易排错、低延迟，这一取舍在系统论文语境下是合理且自洽的。
